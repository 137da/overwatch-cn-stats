# 前端工作台与回归验证

界面采用主人审核的柔彩工作台方案：浅蓝导航与主操作、奶油色玩家头卡、按段位着色的职责卡。
龙娘头像继续用于品牌和窗口。所有资源在本地，不增加 UI 框架或网络字体依赖。

## 界面结构

- 左侧：战绩查询、玩家库、举报提醒、账号管理、设置、常用玩家和简要账号状态。
- 查询：玩家资料 → 统计模式与赛季 → 竞技段位 → 六项表现指标 → 对局列表。
- 玩家库、账号管理、举报提醒、设置使用统一面板；查找结果与记分板支持嵌套打开。
- 设置按举报提醒、命令行（CLI）、版本与更新分组；CLI 每日请求上限沿用后端范围 0～5000，
  0 表示不限，只统计 CLI 请求，保存后对之后启动的 CLI 命令生效。
- 竞技职责卡由 `rankName` 映射到整块背景色，同段位同色；未定级和未知段位统一灰色。
  快速模式没有竞技段位，也使用统一灰色。补查的历史段位保留原赛季与提示。
- 统计数字平铺；保留赛季胜率、场次、近期胜率、场均击杀、伤害、治疗以及常用英雄。
  “近 12 场 · 主玩职责”继续标明近期指标的统计口径。

取样规则：对 RGBA 图像保留 alpha > 220 且 HSV 明度在 (0.25, 0.9) 内的像素，
排除透明边缘、最暗描边与最亮高光，对保留像素的 RGB 各通道取算术平均并四舍五入。
翡翠宣传图先截取原图像素区域 `(300, 50, 750, 380)`（左、上、右、下），
再限定 HSV 色相在 (0.34, 0.49)、饱和度 > 0.25，排除粉色宣传背景。
背景各通道为 `round(取样值 × 0.22 + 255 × 0.78)`；文字为 `round(取样值 × 0.58)`。

## 交互与请求边界

- 竞技／快速统计切换只重绘已有数据；对局模式与分页继续发送 `stats=false`。
- 打开账号或举报面板不会自动发起战绩查询；举报检查仍需手动开启。
- 查询进行中禁用重复入口；旧分页、旧扫码、旧对局详情响应不会覆盖新状态。
- 查询中收到新举报时，等当前查询成功结束再顺序查询；当前查询失败则不追加自动请求。
- 对局行支持键盘操作，面板支持焦点约束与关闭后焦点恢复，Escape 只关闭顶层。
- 重新获取二维码、加载、过期、失败、空数据及错误提示使用明确的可见状态。
  封禁与限流不自动重试；网络失败可手动重试，凭据过期提供重新扫码入口。
- 最小桌面窗口为 820×600。更窄的浏览器预览按区块重排，表格局部横向滚动。

## 浏览器回归

测试只用虚构数据和模拟 `window.pywebview.api`，不读取凭据，不连接真实游戏接口。

1. 在项目根目录启动静态页面：

   ```powershell
   python -m http.server 18765 --bind 127.0.0.1 --directory "ow_desktop/web"
   ```

2. 在 Playwright 的 `page` 上先调用
   `page.addInitScript({path: "docs/frontend_fixture.js"})`。
3. `docs/frontend_smoke.js` 的内容是一个异步函数表达式。将它作为
   Playwright `browser_run_code` 的代码执行（或使用工具的 `filename` 参数）。
   默认结果截图写入项目的 `build/`，可通过第二参数更改 `baseUrl`、`artifactDir`。

验证覆盖：无额外启动查询、六项统计、段位与无段位配色、模式切换请求参数、分页、赛季、
玩家库检索、账号展开及切换、举报开关、设置保存（含 CLI 上限回显、正常值、零值、边界与非法输入）、嵌套记分板、键盘焦点、
1440/1100/820/360 像素布局、错误恢复、重复查询、二维码过期和扫码返回。

`docs/frontend_edge_smoke.js` 通过相同方式执行，覆盖迟到的详情与分页、全部未定级、
未知段位、空统计、HTML 转义、分页桥接异常和取消扫码后的迟到响应。

原生窗口验证另使用只返回虚构数据的 Python 桥接，在实际 WinForms/WebView2 中确认
资源加载、符号图标、面板打开及样式。真实账号扫码和游戏数据不在模拟回归的覆盖范围内。
